# 中间产物格式契约

所有产物落盘到审计工作目录（用户指定，或默认 `audit_output/`），UTF-8 编码。

## 1. audit_plan.md（L0 产出）

```markdown
# 审计计划
- 项目: <名称/路径>
- 语言/框架: <...>
- 规模: <文件数 / 估算行数 / 估算总 token>
- 审计维度: <本轮重点，默认全量>

## 分组与优先级
| 组 | 路径/模块 | 文件数 | 估算token | 优先级 | 顺序 |
|----|-----------|--------|-----------|--------|------|
| g1 | src/core  | 12     | ~25K      | 高     | 1    |
| g2 | src/api   | 8      | ~18K      | 高     | 2    |
| g3 | tests     | 30     | ~40K      | 低     | 4    |

## 审计顺序
1. g1 → g2 → g3 （互不依赖的组可并行）
```

## 2. findings/<group>.md（L1 产出）

```markdown
# 审计发现 - <组名>

## [高] src/core/Engine.cs:142 — 空引用
- 描述: 未判空直接访问，异常路径会崩
- 根因: 上游返回 null 未校验
- 建议: 增加判空 + 返回错误码

## [中] src/core/Engine.cs:88 — 性能
- 描述: 循环内重复解析正则
- 建议: 正则实例移到类字段缓存
```

条目规则：
- 每条固定标题：`[严重度] 文件:行号 — 问题类型`
- 同一文件多条按行号升序
- 无法定位行号时，给出可检索的符号名/类名+方法名

## 3. findings_summary.md（L2 产出）

```markdown
# 审计汇总
- 覆盖: <组数 / 文件数>
- 高/中/低: <x / y / z>

## 高严重度
| 文件:行 | 类型 | 问题摘要 | 来源组 |
|---------|------|----------|--------|
| src/core/Engine.cs:142 | 空引用 | 未判空 | g1 |

## 中严重度
...

## 按模块分布
| 模块 | 高 | 中 | 低 |
|------|----|----|----|

## 重复合并说明
<哪些跨组重复被合并，保留主条目>
```

## 4. audit_report.md（L3 产出）

```markdown
# 代码审计报告 - <项目名>
- 日期 / 审计范围 / 规模 / 审计维度

## 一、概述
总体健康度、关键结论 3-5 条

## 二、核心发现（高严重度优先）
按严重度分组，每条含证据（文件:行）+ 建议

## 三、模块分布
表格或列表

## 四、系统性问题（根因归纳）
同类问题的共同根因，1-N 条

## 五、修复建议（按优先级）
P0 立即 / P1 近期 / P2 规划，每条给出文件与具体做法
```

## 审计工作目录约定
- 每轮审计新建时间戳子目录：`audit_output/<项目名>_<YYYYMMDD>_<HHMM>/`
- 续跑检测：若已存在 `findings_summary.md`，先向用户确认"续跑（跳过已完成组）还是重跑"
- 片级清单按组命名，追加写入而非覆盖，保证可恢复
