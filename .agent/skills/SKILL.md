# 代码审计流水线

对代码库做结构化、可追溯、可恢复的审计。**拆小颗粒、每步落盘、最后汇总**——每层窗口独立，中间产物全部落盘，靠文件传递状态而非模型记忆。

## 总流程（4 层）

### L0 结构扫描 → 审计计划
1. 读取项目元信息：目录树、文件清单、语言/框架识别（package.json / *.csproj / Cargo.toml / pyproject.toml / requirements.txt / go.mod 等）
2. 按模块/目录/依赖关系把文件分组，估算每组规模（token 量级），定优先级
3. 产出并落盘 `audit_plan.md`：文件分组、每组优先级(高/中/低)、审计顺序、本轮审计维度

### L1 逐片审计（可并行）
按审计计划逐组执行，每组一个独立窗口：
1. 载入「审计规范」固定前缀（`references/audit-dimensions.md` 或用户指定重点）
2. 只读本组文件内容（**禁止**把整个项目塞进上下文）
3. 逐文件审计，每条问题追加到 `findings/<group>.md`
4. 本组完成立即落盘，不保留跨组记忆

### L2 汇总去重
1. 读取全部片级清单，合并、去重（跨组重复的问题合并）
2. 按严重度排序 + 按文件/模块归类
3. 落盘 `findings_summary.md`

### L3 审计报告
基于汇总清单生成 `audit_report.md`：
- 概述：审计范围、规模、总体健康度
- 核心发现：按严重度分组（高严重度优先）
- 模块分布：问题在各模块的分布
- 系统性问题：同类问题归纳成根因
- 修复建议：Quick wins / 高风险 / 结构性重构，标注优先级

## 审计规范
- 默认审计维度与严重度判定：`references/audit-dimensions.md`
- 用户可指定重点（如"只查安全和并发""只看性能瓶颈"）
- 语言特定检查：按项目语言加载 `references/audit-dimensions.md` 对应语言节

## 中间产物契约
- 所有中间产物落盘到审计工作目录（用户指定或默认 `audit_output/`）
- 格式模板：`references/output-formats.md`（audit_plan / findings / summary / report 四类）
- 报告每条结论必须可追溯到来源文件+行号

## 执行纪律
- 每片只读本组文件，上下文永远受控
- 每步产出立即写盘，靠文件传状态
- 互不依赖的组可并行（多 agent / 多槽）
- 中途中断可从最后落盘状态续跑，不重来
