# g5 组审计发现：UI 面板与监控页（StatusPanelView / StatsPanelView / SlotPanelView / MonitorPanelView / PerfMonitorView / PerfTrendChart）

> 审计范围：StatusPanelView.cs / StatsPanelView.cs / SlotPanelView.cs / MonitorPanelView.cs / PerfMonitorView.cs / PerfTrendChart.cs
> 重点复查：C1（Font 释放，PerfTrendChart 已做修复样板）

## 发现清单

- [中] MonitorPanelView.cs:400-447 — UpdatePropsCard 每次刷新泄漏控件 + RowStyles 无界增长
  - 触发条件：点击「手动刷新」按钮（可无限次触发）
  - 代码路径：Refresh() → UpdatePropsCard(snap) → `_tblPropsBody.Controls.Clear()`（:400 只移除不 Dispose）→ 每行 new 3 个 Label + new Font（:409-444）→ `_tblPropsBody.RowStyles.Add(...)`（:431 只增不减）
  - 破坏后果：每次刷新累积约 20-70 个 Label 控件 + 等量 GDI Font 句柄 + RowStyles 行样式条目；控件不 Dispose 导致句柄无界增长（GDI 上限 10000 触发绘制异常），RowStyles 持续追加导致 TableLayoutPanel 布局计算线性恶化、行错位
  - 修复：刷新前遍历旧行控件 Dispose 并清空 RowStyles（`_tblPropsBody.Controls.Clear()` 前逐项 `Dispose()` + `RowStyles.Clear()`）；Font 用静态缓存字体

- [中] StatusPanelView.cs:251-266 — RefreshInFlightTasks 每次重建 Label 不 Dispose（GDI 累积）
  - 触发条件：调度器 InFlightChanged 事件（每次请求进出/完成触发）
  - 代码路径：RefreshInFlightTasks() → `_inFlightPanel.Controls.Clear()`（:253 只移除不 Dispose）→ 每个在途任务 new Label + new Font（:256-263）
  - 破坏后果：任务进出频繁时每事件累积 N 个 Label + N Font GDI 对象；长会话（如知识库批量任务）累积数百上千句柄，最终 GDI 耗尽
  - 修复：Clear 前遍历旧 Label Dispose；或维护固定 Label 池按需显隐

- [低] StatusPanelView.cs:92/:105/:111/:119/:125/:131/:137/:143/:162/:259 + StatsPanelView.cs:22 + SlotPanelView.cs:45 + MonitorPanelView.cs:82/:93/:106/:123/:167/:389/:414/:424/:439 + PerfMonitorView.cs:74/:84/:106/:180/:236/:485/:495 — C1 延续：构建期 `new Font(...)` 不 Dispose（有界泄漏）
  - 触发条件：启动构建 UI（一次性）；对比 PerfTrendChart.cs:31-57 已做 C1 修复样板（实例字段 + Dispose 释放）
  - 代码路径：各 View 构建方法/字段初始化器直接 new Font；控件持有引用但窗体/控件 Dispose 不释放 Font
  - 破坏后果：每次启动泄漏 ~40 个 GDI Font 句柄（进程不退出不回收）；非无界但违反 IDisposable 规范，且与本文件组内 PerfTrendChart 的修复标准不一致
  - 修复：仿 PerfTrendChart——Font 提升为实例/静态字段统一创建与释放，或 UiTheme 提供字体工厂缓存

- [低] MonitorPanelView.cs:190 — Refresh() 用 `new` 隐藏基类 Control.Refresh()（语义覆盖）
  - 触发条件：任何以 MonitorPanelView 引用的调用方调用 Refresh()（含未来重构误用）
  - 代码路径：`public new async void Refresh()` 隐藏 Control.Refresh（invalidate+update）；async void 已有 try/catch 包裹（:236-240，P0-H-03 同款防护）
  - 破坏后果：调用方期望"刷新控件显示"却触发 HTTP 采集链（CPU 采样 + 3 接口请求）；当前仅按钮点击一处调用，无实际触发路径，属命名/语义风险
  - 修复：更名 RefreshNow/CollectAndRefresh，消除隐藏基类成员

- [低] PerfMonitorView.cs:276-319 — OnTick 每 1s 在 UI 线程做全量聚合（Series.Snapshot + ComputeSummary + Last(ChartPoints) 拷贝）
  - 触发条件：监控页常驻（定时器 1s）
  - 代码路径：OnTick → _chart.SetData(Series.Last(...)) + PerfAnalyzer.ComputeSummary(Series.Snapshot()) + _timing.Stats() + CheckAlarms
  - 破坏后果：每 1s UI 线程 O(n) 扫描全部采样点；300 点窗口下微秒级可接受，但计算量与 Series 容量线性增长，长期会话后每 tick 成本上升（当前无实际卡顿证据，防御性）
  - 修复：仅当 Series 版本变化时重算；ComputeSummary 改增量维护

- [低] PerfMonitorView.cs:379-431 — RefreshLogSummary 在 UI 线程同步解析 perf.log 文件
  - 触发条件：点击「刷新日志摘要」按钮 / 监控页构建时（:251）
  - 代码路径：RefreshLogSummary → PerfAnalyzer.ParsePerfLog + ParseSessions（全文件读 + 正则解析）
  - 破坏后果：perf.log 最大 5MB（5MB×3 轮切），解析约几十 ms；UI 线程短暂阻塞（当前可接受，无卡顿证据）
  - 修复：Task.Run 解析后 InvokeOnUi 回填（可选优化）

- [低] PerfMonitorView.cs:464-473 — RefreshMetricBtns 每次调用新建 string[] keys 数组
  - 触发条件：OnTick 每 1s + 指标切换点击
  - 代码路径：RefreshMetricBtns 内 `string[] keys = {...}` 每 tick 重新分配
  - 破坏后果：每 1s 一次 5 元素数组分配（可忽略）；可提升为静态只读字段
  - 修复：static readonly string[] MetricKeys

- [低] PerfTrendChart.cs:200-205 — DrawPolyline 参数 n 未使用（死参数）
  - 触发条件：代码维护
  - 代码路径：DrawPolyline(g, pts, plot, yMin, span, n)，方法体内 n 未引用（仅 pts.Count 判断）
  - 破坏后果：无行为影响，纯冗余参数
  - 修复：删除 n 参数

- [低] SlotPanelView.cs:167-187 — OnSlotMgmtCellChanged 列号魔法值（case 3/4 硬编码）
  - 触发条件：槽位管理页编辑 CheckBox / 列结构调整时
  - 代码路径：e.ColumnIndex switch { case 3: 强占; case 4: KV缓存 }，与 BuildMgmtPage 列序（:68-70）隐式耦合
  - 破坏后果：列顺序调整后误写列；当前行为正确

- [观察] SlotPanelView.cs:113-139 — RefreshSlotMgmtGrid 只 upsert 不删除已消失的绑定行
  - 触发条件：绑定条目被删除（当前 SlotAffinity 绑定表无删除路径，g2 已确认绑定无界增长）
