# g4 组审计发现：UI 外壳（MainForm / Ui / Config / Presenter / UiTheme / MarkdownRenderer / LogView / Program）

> 审计范围：MainForm.cs / MainForm.Ui.cs / MainForm.Config.cs / MainFormPresenter.cs / UiTheme.cs / MarkdownRenderer.cs / LogView.cs / Program.cs
> 重点复查：C1（控件 Font=new Font 未释放）

## 发现清单

- [中] MainForm.Ui.cs:319-348 — ShowDocInPanel 每次点击泄漏 GDI 对象（RichTextBox + Font 无界累积）
  - 触发条件：反复点击「使用说明/常见问题/更新内容」任意按钮
  - 代码路径：btnHelp/btnFaq/btnChangelog.Click → ShowDocInPanel(_docPanel,...)；方法内 `container.Controls.Clear()` 只移除不 Dispose，随后 new RichTextBox + new Font("Microsoft YaHei UI", 9F)（:325-332）
  - 破坏后果：每次点击创建 1 个 RichTextBox 控件 + 1 个 GDI Font 句柄且永不释放；文档按钮可无限点击 → GDI 句柄无界增长，进程长期运行后 GDI 耗尽（10000 句柄上限）导致 UI 绘制异常/崩溃
  - 修复：Clear 前遍历旧控件 Dispose（或复用单个 rtb 实例只换文本）；Font 改用 MarkdownRenderer 已缓存的静态字体（M-15 同款模式）

- [低] UiTheme.cs:89/:148/:164/:227/:241/:258 + MainForm.Ui.cs:234/:363/:372/:508/:538 + LogView.cs:27 — C1 遗留：构建期 `new Font(...)` 不 Dispose（GDI 泄漏，非无界）
  - 触发条件：启动构建 UI（一次性约 40-60 个 Font 句柄）；MakeRawButton/MakeRawTextBox 每次调用 +1
  - 代码路径：UiTheme.MakeBtn/MakeSectionTitle/MakeTabBtn/MakeCardTitle/MakeRawButton/MakeRawTextBox、MainForm.BuildTitleBlock/NewGroup/AddRow、LogView.TxtLog 初始化器
  - 破坏后果：WinForms 控件 Dispose 不释放 Font（需显式 Dispose 或共享静态实例）；每次启动泄漏数十个 GDI 字体句柄，进程不退出前不回收。量级有限（非无界），但违反 IDisposable 规范，与 M-15/M-16 修复方向不一致
  - 修复：仿 MarkdownRenderer M-15——静态缓存常用 Font 实例复用；控件持有 Font 时统一从工厂取

- [低] MainForm.Ui.cs:260-270 — 页签索引魔法值（SelectTab(3/6/7) 硬编码）
  - 触发条件：新增/删除页签后侧边栏按钮指向错页
  - 代码路径：btnSlotMgmt.Click→SelectTab(3)；btnOpenConfig.Click→SelectTab(6)；btnHelp/btnFaq/btnChangelog→SelectTab(7)；:415 页签名数组 names[] 与索引隐式耦合
  - 破坏后果：此前已发生一次实际事故（v2.23.2 注释"性能监控插入后索引 6→7"自证）；下次插入页签会再次错位
  - 修复：页签名 → 索引的静态映射（如 `TabIndexes.Config = 6`）或按页签名查 index

- [低] MainForm.Config.cs:13-56 — ApplyConfigToUi 写控件触发 TextChanged → OnParamEdited 连锁全量同步
  - 触发条件：启动加载配置 / 导入配置文件时
  - 代码路径：ApplyConfigToUi 设置 40+ 控件 .Text/.Checked → 每个触发 WireEvents 订阅的 OnParamEdited → SyncConfigFromUi 全量读回 40+ 控件（TryParse/clamp）
  - 破坏后果：配置加载路径做 40×2 冗余同步（写 40 次 + 读 40 次），行为等价（读回值 == clamp 后写入值）但重复工作；未来若 ReadInt 与 Apply clamp 逻辑漂移会引入隐性 bug
  - 修复：ApplyConfigToUi 期间置 _applyingConfig 标志（OnParamEdited 直接 return），或事件去抖

- [低] MainFormPresenter.cs:176/:223 — MessageBox.Show 直接调用（线程假设不一致）
  - 触发条件：若未来从后台线程调用 OnExportConfigClicked/OnImportConfigClicked（当前仅 UI 线程事件调用）
  - 代码路径：OnExportConfigClicked catch 块 MessageBox.Show(_view,...)；OnImportConfigClicked catch 块同上；对比 OnStartClickedAsync（:106）已用 InvokeOnUi 包裹
  - 破坏后果：跨线程调用 MessageBox.Show 抛 InvalidOperationException；当前无触发路径，属一致性/防御问题
  - 修复：统一走 _view.InvokeOnUi(() => MessageBox.Show(...))

- [低] MainFormPresenter.cs:229 — OnParamEdited 每次按键全量 SyncConfigFromUi（40+ 控件 TryParse/clamp）
  - 触发条件：用户输入任一参数（TextChanged 逐键触发）
  - 代码路径：WireEvents 40 个控件事件 → OnParamEdited → SyncConfigFromUi 遍历全部控件
  - 破坏后果：每键全量同步 40 控件（微秒级，性能可接受）；但在高频 TextChanged 下重复计算，且与配置导入路径叠加放大
  - 修复：300ms 去抖或仅同步变更控件（收益低，可选）

- [低] MainForm.Ui.cs:471 — `if (c is TextBox tb)` 冗余判断
  - 触发条件：代码阅读/维护
  - 代码路径：BuildConfigPanel foreach(new[]{_txtExe,...}) 数组元素本就是 TextBox，is 判断恒真
  - 破坏后果：无行为影响，纯风格冗余
  - 修复：直接 `tb.ForeColor = Color.White` 或改强类型数组
