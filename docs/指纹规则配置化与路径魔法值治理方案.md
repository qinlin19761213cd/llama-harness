### 1.2 业务前缀硬编码（核心问题）

**A. `SlotAffinity.GetAffinityKey()`（L53-78，static）**——4 组指纹匹配写死在方法体内：

| 优先级 | 匹配方式 | 命中的 key | 说明 |
|---|---|---|---|
| 1 | 头 `x-deepseek-harness-user-id` 非空 | `dsh_rule_{uid}` | DSH 规则引擎，用户级永久绑定 |
| 2 | 头 `X-Conversation-Id` 非空 | `webui_{cid}` | WebUI，会话级绑定 |
| 3 | 头 `x-model-provider` == `custom_openai_compatible` | `trae_global` | Trae Work 独家特征头 |
| 4 | UA 含 `deepseek-harness` **且** 存在 `X-Stainless-*` 头 | `dsh_agent_global` | DSH 主 Agent |

**B. `SlotAffinity.AppNameOf()`（L81-88，static）**——4 组前缀 → 显示名硬编码 if-else（`trae_`→"Trae Work" / `webui_`→"WebUI" / `dsh_rule_`→"DSH 规则引擎" / `dsh_agent_`→"DSH 主 Agent"）。

**C. MainForm UI 层**——8 个 CheckBox 与 4 个业务前缀强耦合：
- `MainForm.Ui.cs` L49-57：`_chkAutoPre{DshRule,Webui,Trae,DshAgent}` + `_chkSnap{DshRule,Webui,Trae,DshAgent}` 硬编码声明；
- `MainForm.Config.cs` L51-60 / L106-115：CheckBox ↔ 前缀字符串（`"dsh_rule"`/`"webui"`/`"trae_global"`/`"dsh_agent_global"`）双向映射写死。

**D. 已配置化但 UI 写死的部分**：`AppConfig.AutoPreemptiveApps`（默认 `"dsh_agent_global,trae_global"`）、`AutoSnapshotKeys`（默认 `"trae_global"`）已支持逗号分隔前缀配置，但 UI 只认 4 个固定 CheckBox——配置里新增前缀后 UI 无入口，且无法展示。

**结论**：新增一类业务客户端（如新的 Agent / IDE / 工具链）需要改 `GetAffinityKey` + `AppNameOf` + `MainForm.Ui` + `MainForm.Config` 四处代码；且 `GetAffinityKey` 是 static，无法按实例定制规则、无法在测试中注入替代规则。

## 2. 设计目标与红线

### 2.1 目标

1. **路径单一入口**：新增 `AppPaths` 静态类，集中全部目录/文件路径，消除 9 处散落拼接 + 3 份重复 `EnsureConfigDir`；
2. **指纹规则配置化**：把 4 组指纹匹配从 `GetAffinityKey` 静态方法体抽成 **config.json 内可配置的有序规则表**（`affinity_rules`），匹配由规则引擎按优先级自动执行——**新增业务只改配置，零代码改动**；
3. **GetAffinityKey 去 static**：改为实例方法，规则表随实例注入，可测试、可定制；
4. **魔法值命名化**：按类别把残留魔法值收敛为具名常量（已有 O-11 常量不动）。

### 2.2 红线

- **行为等价**：默认规则下，4 类请求经 `GetAffinityKey` 产出的 key 与现状**逐字一致**（`dsh_rule_{uid}` / `webui_{cid}` / `trae_global` / `dsh_agent_global`）；
- **不动既有语义**：`AutoPreemptiveApps` / `AutoSnapshotKeys` 仍按 **key 前缀**匹配（独立于规则引擎），规则化后它们的判定结果不变（KvSaveTimingTests 覆盖）；
- **零新依赖**：仅用 System.Text.Json（已在用）；
- **可回退**：每步独立 `dotnet build` 0 警告 0 错误 + 82 测试全绿 + 独立 commit。

## 3. 分步方案

### Step 1：AppPaths 统一路径管理（新文件 `LlamaHarness/AppPaths.cs`）

**类规格**：

```csharp
/// <summary>全项目路径单一入口（v2.16）：消除散落 Path.Combine(BaseDirectory, "config"/"logs"/"static", ...)。</summary>
public static class AppPaths
{
    // —— 目录根 ——
    public static string BaseDir { get; } = AppContext.BaseDirectory;
    public static string ConfigDir { get; }   // BaseDir/config
    public static string LogDir { get; }      // BaseDir/logs
    public static string StaticDir { get; }   // BaseDir/static

    // —— config/ 下的持久化文件 ——
    public static string ConfigJson { get; }        // config/config.json
    public static string SlotBindingsJson { get; }  // config/slot_bindings.json
    public static string KvCacheIndexJson { get; }  // config/kv_cache_index.json
    public static string RestoreStatsJson { get; }  // config/restore_stats.json

    // —— logs/ 下的日志文件 ——
    public static string HarnessLog / WarnErrorLog / SlotLog / RequestDumpLog / UnhandledLog { get; }

    // —— static/ ——
    public static string IconFile(string fileName); // static/icon/{fileName}

    // —— 目录保证（幂等，替代 3 份重复 EnsureConfigDir）——
```

### Step 2：AffinityRules 指纹规则引擎（核心）

**2a. 配置模型扩展**（AppConfig.cs 新增，snake_case 持久化）：

```csharp
/// <summary>指纹识别规则（有序按 Priority 升序匹配，第一条命中即返回）。
/// 新增业务 = 在 config.json 的 affinity_rules 追加一条，零代码改动。</summary>
public List<AffinityRule> AffinityRules { get; set; } = DefaultAffinityRules();

/// <summary>规则匹配方式：Header=取头值替换 KeyTemplate；HeaderValue=头值等于指定值→固定 Key；UaAndHeaderPrefix=UA 含 UaContains 且存在 HeaderPrefix 前缀头。</summary>
public enum AffinityMatchType { Header, HeaderValue, UaAndHeaderPrefix }

public sealed class AffinityRule
{
    public string Id { get; set; } = "";            // 业务标识，如 "dsh_rule"
    public string Name { get; set; } = "";          // 显示名，如 "DSH 规则引擎"
    public AffinityMatchType Match { get; set; }
    public string Header { get; set; } = "";        // 头名（Header / HeaderValue 用）
    public string Value { get; set; } = "";         // 期望头值（HeaderValue 用）
    public string UaContains { get; set; } = "";    // UA 子串（UaAndHeaderPrefix 用）
    public string HeaderPrefix { get; set; } = "";  // 头名前缀（UaAndHeaderPrefix 用）
    public string KeyTemplate { get; set; } = "";   // 含 {value} 占位（Header 用）
    public string Key { get; set; } = "";           // 固定 key（HeaderValue / UaAndHeaderPrefix 用）
    public int Priority { get; set; }               // 越小越先匹配
}

private static List<AffinityRule> DefaultAffinityRules() => new()
{
    new() { Id="dsh_rule",   Name="DSH 规则引擎", Match=Header, Header="x-deepseek-harness-user-id", KeyTemplate="dsh_rule_{value}", Priority=1 },
    new() { Id="webui",      Name="WebUI",        Match=Header, Header="X-Conversation-Id",          KeyTemplate="webui_{value}",   Priority=2 },
    new() { Id="trae_global",Name="Trae Work",    Match=HeaderValue, Header="x-model-provider", Value="custom_openai_compatible", Key="trae_global", Priority=3 },
    new() { Id="dsh_agent",  Name="DSH 主 Agent", Match=UaAndHeaderPrefix, UaContains="deepseek-harness", HeaderPrefix="X-Stainless-", Key="dsh_agent_global", Priority=4 },
};
```

JSON 形态（默认 4 条，与现状逐字等价）：

```json
"affinity_rules": [
  { "id": "dsh_rule", "name": "DSH 规则引擎", "match": "header", "header": "x-deepseek-harness-user-id", "key_template": "dsh_rule_{value}", "priority": 1 },
  { "id": "webui", "name": "WebUI", "match": "header", "header": "X-Conversation-Id", "key_template": "webui_{value}", "priority": 2 },
  { "id": "trae_global", "name": "Trae Work", "match": "header_value", "header": "x-model-provider", "value": "custom_openai_compatible", "key": "trae_global", "priority": 3 },
  { "id": "dsh_agent", "name": "DSH 主 Agent", "match": "ua_and_header_prefix", "ua_contains": "deepseek-harness", "header_prefix": "X-Stainless-", "key": "dsh_agent_global", "priority": 4 }
]
```

**2b. `GetAffinityKey` 去 static（SlotAffinity.cs）**：

- 构造签名扩展：`SlotAffinity(int slotCount, int maxWaitSeconds = 30, IReadOnlyList<AffinityRule>? rules = null)`——rules 为空时用 `AppConfig.DefaultAffinityRules()`（向后兼容：现有 `new SlotAffinity(2)` 测试不传 rules 仍工作）；
- `GetAffinityKey(NameValueCollection h)` 改为**实例方法**：按 Priority 升序遍历规则，逐条执行匹配（`Header` / `HeaderValue` / `UaAndHeaderPrefix` 三种匹配器），第一条命中返回 `KeyTemplate` 替换后的值或固定 `Key`；全不命中返回 `null`（走随机槽，不建绑定）；
- 内部 L101 `var key = GetAffinityKey(headers);` 不变（实例方法内直接调用）；
- **static→instance 波及面极小（已实证）**：`GetAffinityKey`/`AppNameOf` 均无外部调用；唯一实例化点 `SmartScheduler.Lifecycle.cs L156`（`new SlotAffinity(_cfg.Parallel)` → `new SlotAffinity(_cfg.Parallel, rules: _cfg.AffinityRules)`）；测试不直接调 static（经 `GetSlot(headers)` 间接覆盖 dsh_rule_ 路径）。

**2c. `AppNameOf` 从规则表派生（SlotAffinity.cs）**：

- 改为实例方法，按规则表前缀匹配显示名：对每条规则，若 key 以 `Key` 开头（固定 key 规则）或 `KeyTemplate` 前缀开头（模板规则，取 `{value}` 前段）→ 返回 `Name`；
- 全不命中 → "未知应用"（现状 L87 同语义）；
- 兼容：`trae_global` 命中 `Key`；`webui_xxx` 命中 `KeyTemplate` 前缀 `webui_`。

**2d. UI 联动（本步仅做前缀集合的读取侧兼容）**：MainForm 现有 4 个 CheckBox **保持不动**（它们映射 `AutoPreemptiveApps`/`AutoSnapshotKeys` 的前缀集合，独立于规则引擎）。规则表新增业务后，用户可**直接在 config.json 的 auto_preemptive_apps / auto_snapshot_keys 手填新前缀**生效（已支持），UI 动态化见 Step 4（可选）。

**2e. 规则引擎新文件 `LlamaHarness/AffinityRuleMatcher.cs`**：匹配逻辑独立成静态工具（可单测），SlotAffinity 调它：

```csharp
public static class AffinityRuleMatcher
{
    public static string? Match(NameValueCollection headers, IEnumerable<AffinityRule> rules); // 按 Priority 升序，首中即返
    public static string? ResolveKey(AffinityRule r, string headerValue); // Header 模板替换
    public static string AppNameOf(string key, IEnumerable<AffinityRule> rules); // 规则派生显示名
}
```

**验收**：新增规则引擎单测（默认 4 规则对 4 类请求的 key 与现状逐字一致 + 大小写不敏感 + 优先级顺序 + 新增自定义规则可识别）；82 旧测试全绿；build 0 警告 0 错误。

## 4. 兼容性与风险

| 风险 | 应对 |
|---|---|
| 规则配置损坏 / 字段缺省 | 加载容错：单条规则解析失败跳过 + 记录日志；`affinity_rules` 为空或异常时回退 `DefaultAffinityRules()`（与现状等价） |
| `AffinityMatchType` 枚举 JSON 序列化 | 用字符串枚举转换（`match` 存 snake_case 字符串，加载时解析，兼容缺省→Header） |
| AppNameOf 派生语义变化 | 默认 4 规则下逐条对照现状 4 个 if；测试断言显示名 |
| static→instance 漏改调用 | 已实证无外部调用；改后 `dotnet build` 强制暴露（编译期兜底） |
| 与 `AutoPreemptiveApps`/`AutoSnapshotKeys` 前缀匹配的交互 | 两者独立按 key 前缀判定，规则化不影响；KvSaveTimingTests 全绿保底 |
| 既有 config.json 无 `affinity_rules` 字段 | 反序列化缺省 → 默认 4 条；老配置文件无需迁移（字段可空） |
