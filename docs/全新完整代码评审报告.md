## 四、核心问题清单

### 高风险

1. SmartScheduler 仍是核心单点：2000+ 行，承担唤醒、休眠、网关、崩溃恢复、KV 路由、性能埋点、端口探测等职责；维护半径大，回归风险高。
2. _backend 懒初始化与端口变化存在生命周期风险：休眠后再唤醒且端口变化时，请求可能仍打向旧端口；并发首用还可能泄漏 HttpClient。
3. _inflight 计数与登记动作不在同一异常保护域：若中间步骤抛异常，_inflight 可能永久偏高，导致休眠条件永远不满足。
4. KV 缓存去重键和落盘时序存在上下文污染风险：去重键只含 key 不含 slot，跨槽并发 save/restore 仍可能读到半写 .bin。
5. 性能统计口径失真：均值分母被稀释，慢指标缓存延续破坏“持续 N 秒”阈值语义，键名注册表与实际实现不一致。
6. 核心业务路径测试不足：端到端请求路径、OutputContinuer、CrashRecovery、KvCacheManager 磁盘往返、AppConfig.Load/Save、UI/Presenter、LlamaServerProcess、LlamaFinder 缺少稳定回归锁。

### 中风险

7. 多处空 catch 和静默失败：排障成本高。
8. UI 线程仍存在同步阻塞：清缓存、刷新和手动导入时可能卡顿。
9. 持久化策略需要统一：.tmp + Move、.meta.json 与索引写入原子性不足。
10. 配置与亲和规则存在静默失效：Load 依赖单个字段探测，Sanitize 不校验 AffinityRules 空列表。

### 低风险 / 代码异味

1. Console.WriteLine 仍有少量存在
2. async void 虽已收敛，但仍应严格限制在事件入口
3. PerfMonitorView 的图表和摘要刷新仍有重复扫描
4. react-demo 中 TodoList 缺少完成状态切换，功能不完整
5. docs 中有草稿、无关项目文档、过期基线数字和未合并重复方案
