# LlamaHarness 性能监控模块设计方案

- 版本：v2.21（2026-09-01，方案批准 + 7 步实施完成）
- 依据：用户需求「给系统增加性能监控模块」+ 用户 3 条补充建议（网关时延采样 / 统一标准化采集格式与独立性能日志 / 独立模块分析性能日志）
- 实施分支：`refactor/mainform`

---

## 1. 背景与现状缺口

改造前监控能力（无时间线、无历史、无阈值）：

| 能力 | 现状 | 缺口 |
| ---- | ---- | ---- |
| 系统资源 | SystemMetrics 手动触发瞬时采样（CPU/内存/显存） | 无时间序列，无法回答「显存是否爬升」 |
| llama.cpp 监控 | LlamaCppMonitorCollector 手动触发三接口快照 | 无历史，无法看吞吐趋势 |
| Token 统计 | StatsPanelView 会话内聚合 | 无 tps 时间线 |
| 请求时延 | 无 | 无法定位网关/后端耗时分布 |

核心痛点：无法回答「显存是否爬升 / tps 是否骤降 / KV 是否逼近上限」三类趋势性问题。

## 2. 用户 3 条补充建议的分析与边界修正

### ① 网关节点数据采样（含接收/转发/输出时间）
- **合理采纳**：增加网关时延采样（t_recv / t_forward / t_complete 三段），并细分为四段——**唤醒等待 / 网关预处理 / 后端推理+SSE 转发 / 总时延**（用户三段中「转发时间」拆为「后端推理+SSE 转发」与「网关预处理」两段，更利于归因：唤醒慢 vs 预处理慢 vs 后端慢）。
- **边界修正**：时延是**事件驱动**（有请求才有），与系统指标的**周期采样**形态不同，不能硬塞进轮询采样器——作为独立 `RequestTiming` 事件流，仅推理请求记录。

### ② 统一标准化所有性能采集格式 + 性能参数单独输出日志
- **合理采纳**：统一为强类型 `PerfPoint`（内存侧）+ 机器可解析 `perf.log`（落盘侧，每行 `Kind,ts,key=value,...`，分 system/cpp/gateway 三类）。
- **边界修正（关键）**：perf.log **不走 LogPipeline 主有界队列**（50k 四流共享单写线程）——性能采样 1 行/秒且高频，会挤占主日志；采用**独立常驻 StreamWriter 直写 + 独立 5MB×3 轮切**。**统一的是格式协议，不是写入通道**（最容易踩的坑）。

### ③ 独立模块对性能日志做分析
- **合理采纳**：`PerfAnalyzer` **双源共享分析内核**——实时（读内存环形缓冲做趋势/告警）+ 离线（读 perf.log 做跨会话对比/异常窗口定位），共用同一套指标键与阈值规则语义，避免「实时图与历史分析对不上」。

## 3. 架构总览

```
┌─ 周期采样（1s/5s）─────────────────────────┐   ┌─ 事件采集（请求级）──────────────┐
│ PerfSampler                               │   │ RequestTimingTracker           │
│  ├ 1s: CPU/内存/inflight（SystemMetrics） │   │  ├ Begin(t_recv)               │
│  └ 5s: 显存(nvidia-smi)/llama.cpp 三接口  │   │  ├ MarkReady(t_ready) 唤醒完成 │
│        （慢指标异步，缓存延续填充曲线）    │   │  ├ MarkSent(t_sent)   发向后端 │
└──────────────┬────────────────────────────┘   │  └ Complete(t_complete) 四段   │
               │ PerfPoint（统一模型）          │        + 最近200环形+会话聚合   │
               ▼                                └──────────────┬───────────────┘
        PerfSeries（3600点环形缓冲≈1h）                        │ RequestTiming
               │                                               ▼
               ├──────────────────┬────────────────────────────┘
               ▼                  ▼
        PerfLog（独立直写 perf.log，5MB×3 轮切，AutoFlush）
               │  system/cpp/timing 三类行
               ▼
        PerfAnalyzer（双源共享分析内核：阈值告警/趋势摘要/离线解析）
               ▲
        PerfThresholdRule（配置驱动：指标键+方向+警告/严重+持续秒）
               │
        PerfMonitorView（左侧「性能监控」页签：趋势图+实时数字+告警+perf.log摘要）
```

## 4. 数据模型

### 4.1 PerfPoint（周期采样点，struct，全字段可空）
- 系统层：CpuPercent / MemUsedGb / MemTotalGb / VramUsedMb / VramTotalMb
- llama.cpp 层：PpTps / TgTps / TokensCached / CtxUsedPct / SlotsProcessing
- 网关层：Inflight

### 4.2 RequestTiming（请求级事件，四段时延，仅推理请求）
- t_recv（网关接收）→ t_ready（唤醒/排队完成）→ t_sent（发向后端）→ t_complete（响应完成）
- WakeWaitMs / GatewayMs / BackendMs / TotalMs + App / Path / Success

### 4.3 PerfThresholdRule（配置驱动）
- 指标键 + 方向（Above/Below）+ 警告阈值 + 严重阈值 + 最小持续秒数
- 默认 5 条（本机 RTX 3080 20G / 64G 实测基线）：
  - cpu：>90%（warn）/ >97%（crit）持续 30s
  - vram_mb：>15000 / >18500 持续 60s
  - tg_tps：<10 / <3 持续 30s
  - ctx：>0.85 / >0.95 持续 30s
  - total_ms：>60000 / >180000 单次
- 新增业务/改阈值 = config.json `perf_thresholds` 追加，零代码改动（沿用 v2.16 指纹规则配置化模式）

### 4.4 PerfAlarm
- Ts / Metric / Level（Warn 黄 / Crit 红）/ Value / 中文 Message

## 5. 组件设计

### 5.1 PerfSeries&lt;T&gt;（环形缓冲）
- 定长、写指针环绕、满时覆盖最旧、快照复制不破坏写入、Last(n) 取最近
- 1s 采样 × 3600 点 ≈ 1 小时窗口，内存恒定
- 线程安全（lock），并发冒烟测试通过

### 5.2 PerfSampler（周期采集器）
- 双节奏：1s 轻量指标（CPU/内存/inflight）+ 每 5s 慢指标（显存 nvidia-smi / llama.cpp 三接口）
- 慢指标**异步采集**（SemaphoreSlim 防重叠），不阻塞 1s 快 tick 队列；结果缓存**延续填充**到后续 1s 点（曲线连续，避免 4/5 点为 null）
- cpp 采样按后端端口门控：backendPort=0（未唤醒/手动未启动）自动跳过，端口变化重建 monitor
- 复用 SystemMetrics + LlamaCppMonitorCollector（零重复采集逻辑）

### 5.3 RequestTimingTracker（请求时延追踪器）
- Begin/MarkReady/MarkSent/Complete 四步打点，Stopwatch ticks 计时（抗系统时钟跳变）
- 幂等（Complete 后忽略）、顺序缺失容错（未打点段按 0 计）
- 最近 200 请求环形缓冲 + 会话聚合统计（Completed/Failed/Avg/Max）
- Completed 事件在 lock 外触发（防订阅方回调重入死锁）

### 5.4 PerfLog（统一性能日志）
- 独立常驻 StreamWriter 直写 `logs/perf.log`，AutoFlush（每条立即可读，崩溃不丢已记行）
- 三类行（统一格式协议）：
  - `system,2026-09-01 10:00:00.123,cpu=3.2,mem=28.5,total=64.0,vram=1234,vram_total=8192,inflight=0`
  - `cpp,ts,pp_tps=..,tg_tps=..,tok=..,ctx=0.180,slots=..`
  - `timing,ts,app=..,path=..,success=1,wake=..,gateway=..,backend=..,total=..`
- 5MB × 3 轮切（perf.log → .1 → .2 依次后移删最旧），重启时超限先轮切
- 线程安全（lock）、尽力而为（不抛出）；值内逗号/换行转义保证行可解析

### 5.5 PerfAnalyzer（双源共享分析内核）
- 纯函数、无状态、可单测
- 实时：EvaluatePoints（连续窗口阈值，空值打断，触发后复位防重复刷屏）/ EvaluateTiming（单请求时延）
- 离线：ParsePerfLog（三类行解析 + 请求聚合/失败率/时延极值/峰值显存/最低吞吐/时间范围）
- 共享：ComputeSummary（实时窗口趋势摘要：均值/峰值/最新）
- 指标键统一（PerfAnalyzer.ValueOf），实时与离线共用同一语义

### 5.6 PerfTrendChart（自绘趋势图，零第三方依赖）
- DoubleBuffered 防闪烁；网格/折线/Y 轴语义范围（cpu 0-100、ctx 0-1、其余动态 0~峰值×1.15）/最新值标签/空值断线
- 指标切换：显存（橙）/ CPU（绿）/ 吞吐（蓝）/ KV 占用（黄）

### 5.7 PerfMonitorView（监控页）
- 左侧「性能监控」页签（index 5，插入后配置管理/信息展示索引后移）
- 趋势图 + 实时数字（CPU/内存/显存/吞吐/KV/在途）+ 请求时延统计（请求/失败/失败率/平均/最大/平均后端）+ 告警列表（Warn 黄/Crit 红）+ perf.log 会话摘要（离线分析）
- 1s Forms.Timer 刷新（UI 线程）；阈值告警按 metric+level **5 分钟去重**防刷屏
- 跨线程安全：Timing.Completed 后台事件 BeginInvoke 切回 UI 线程；Shutdown 停表 + 取消订阅

## 7. 测试与验证

- 新增 32 项单测（PerfSeries 9 + PerfSampler 3 + RequestTimingTracker 8 + PerfLog 3 + PerfAnalyzer 9），总计 **171 测试全绿**，构建 0 警告 0 错误
- 覆盖：环形缓冲环绕/快照隔离/Last 语义/并发；采样入环/停止不增长/时间升序；四段时延组装/幂等/容错/聚合/事件/容量/并发；perf.log 三类行格式/未启动 no-op/Start 幂等；阈值连续窗口/方向/空值打断/时延告警/摘要统计/日志解析/缺失文件
- UI 渲染需真实运行手动确认（WinForms GUI 不在命令行验证范围）

## 8. 已知边界与后续可扩展

- **不记录请求级全量 perf 明细**（与 request_dump 语义区分、隐私敏感）
- **不引入第三方图表库/依赖**（趋势图自绘是既定取舍）
- **不建全量时间序列持久化**（只存 1 小时内存窗口 + perf.log 聚合摘要）
- 后续可扩展：perf.log 异常窗口定位的自动化报告导出、阈值配置 UI 化、跨会话对比视图
