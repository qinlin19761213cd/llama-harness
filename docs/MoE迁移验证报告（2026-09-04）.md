# MoE 迁移验证报告

> **验证目标**：将资源治理体系（KV Cache 全链路复用 + RAMDisk 快照 + 槽位治理）从稠密模型迁移到 MoE 模型后，验证效率收益是否成立、量化提升幅度、定位剩余瓶颈。
>
> **验证日期**：2026-09-04
> **状态**：✅ 完成（数据已实测落盘）
> **版本**：v1.2（实测化：任务工作量实测数据落盘；工作量系数待上次对照数据升级为精确倍率）
> **关联文档**：`架构设计说明书.md`、`可观测体系设计方案.md`、`性能监控模块设计方案.md`

## 一、执行摘要（TL;DR）

| 结论 | 数据 |
|---|---|
| **任务级收益** | Obsidian 知识图谱重建：稠密 2 小时 → MoE **~30 分钟**（**4x**；本次工作量更大，按工作量修正等效 **~5.6x**；本次实测 215/215 笔记、2490 双链、980 图谱关联） |
| **输出解码** | 62 t/s → **152 t/s**（**2.45x**，长任务均值，峰值 158.7） |
| **prefill 增量** | ~917 t/s → **最高 2659 t/s**（**2.9x**，压至 0.38~0.54 ms/token） |
| **算力利用率** | SM 核心 ~30%（估算）→ **100%**（**3~4x**） |
| **KV 复用迁移** | **零改动全迁移**：图谱场景命中率 **87%**，缓存判定零误差（wrapper_hit=1 / false_miss=0） |

**一句话结论**：资源治理体系与模型结构无关，KV 复用管线在 MoE 下完整生效；MoE 的稀疏激活（A3B，35B 总参仅 3B 激活）把稠密时代被带宽掩盖的算力潜力全部释放，治理收益 × 模型结构收益叠加，形成任务级 4x 提升。

## 四、带宽与算力分析（为什么 MoE 快）

### 4.1 带宽算术：memory-bound → compute-bound

**稠密 27B（memory-bound）**：
```
decode 每 token 需读整份权重 ~13.5 GB
带宽上限 = 760 GB/s ÷ 13.5 GB ≈ 28 t/s（纯 decode 理论天花板）
SM 单元大部分时间空置等显存喂数据 → 算力参与度低（~30%）
```

**MoE 35B-A3B（compute-bound）**：
```
每 token 仅读激活专家权重 ~1.7 GB（3B 激活 × Q4）
带宽需求降到 ~1/8 → 带宽不再是瓶颈
SM 单元被喂满 → 利用率 100%
```

### 4.2 效率归因拆分

| 因素 | 贡献 | 说明 |
|---|---|---|
| KV 缓存全命中（87%） | **主导**（任务级 4x 主因） | 重复任务重算被跳过，prefill 近零成本 |
| MoE 稀疏激活 | 解码 2.45x | 每步只算 3B 激活，计算量小 + 带宽释放 |
| RAMDisk 快照 | 支撑项 | 磁盘 IO 归零，快照恢复毫秒级 |

> **关键洞察**：2h → 30min 是 **4x 数量级**，远超解码速度的 2.45x。这是 KV 复用让"重算型任务"变成"复用型任务"——同一知识库反复处理时，绝大部分计算在首次已完成，后续只做增量。**且本次工作量大于上次（多链网状 vs 单链放射状），本次实测 980 关联 / 2490 双链 / 5.87 密度，按工作量修正后等效收益 ~5.6x**；知识库越复杂、关系越多 → 重复检索/交叉引用比例越高 → KV 命中率只增不减，复用红利随任务复杂度放大。

## 五、剪刀差与剩余瓶颈

### 5.1 算力提升未完全兑现

```
SM 利用率提升：~3.3x（30% → 100%）
解码吞吐提升：2.45x（62 → 152 t/s）
理论吞吐（若完全兑现）：62 × 3.3 ≈ 205 t/s
实际兑现率：152 / 205 ≈ 75%
```

**约 25% 算力未转成 token**，缺口可能来自：

1. **每步计算量小 → 算子效率受限**：MoE 单步只算 3B，矩阵规模小，SM 调度/启动固定开销占比上升
2. **共享层仍为稠密计算**：attention / KV / 输出投影（unembedding）与 MoE 无关，走全量共享层，成为新的隐藏瓶颈
3. **MTP 投机路径**：compute-bound 下 draft 路径同样吃算力，接受率 80%+ 后边际收益递减

### 5.2 下一步优化方向（候选）

| 优先级 | 方向 | 预期收益 | 状态 |
|---|---|---|---|
| P0 | 专家缓存/预加载（热专家常驻、冷专家按需唤醒） | 压掉专家切换开销，回收部分剪刀差 | 待实施 |
| P1 | MoE 共享层算子融合（attention/unembedding） | 降低共享层稠密计算耗时 | 待评估 |
| P2 | 显存+内存+SSD 混合部署（参考 freetoken，目标 qwen3.8-flash-next） | 突破单卡显存上限，支持更大 MoE | 规划中 |
| P3 | 长任务稳定性持续验证（2h+ 不掉速） | 确认真实生产可用性 | 进行中 |

## 七、结论

1. **方向验证成立**：资源治理体系（KV 复用为核心）与模型结构解耦，MoE 迁移零改动、全生效。
2. **收益可叠加**：治理收益（KV 命中省 prefill）× 模型结构收益（稀疏激活释放算力）= 任务级 4x；本次工作量更大（多链网状），等效收益 **~5.6x**。
3. **硬件的边界被重新定义**：3080 单卡在稠密模型下纯解码带宽上限 ~28 t/s，靠治理翻到 62；MoE 下直接 152 t/s 且 SM 100%——**不是硬件变强，是把硬件吃透了**。
4. **剩余空间明确**：约 25% 算力未兑现（共享层稠密计算 + 专家切换开销），是 MoE 时代的下一站优化目标。
